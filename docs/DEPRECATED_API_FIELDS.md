# حقول API مهجورة — خطة الحذف

> **الحالة:** إلزامي
> **القاعدة:** الحقل المهجور له تاريخ خروج، وإلا صار اسماً دائماً.

كل حقل هنا بقي لسبب واحد فقط: ألا ينكسر شكل استجابة قائمة اليوم. لا شيء
تحت `src/main` يقرؤه، ويمنع اختبار بنيوي أي قارئ جديد:

```
backend/src/test/java/com/waad/tba/modules/member/dto/
    DeprecatedSummaryFieldsHaveNoConsumersTest.java
```

الاختبار يفشل بذكر الملف والسطر والبديل. إذا احتجت الحقل، فالبديل مذكور في
رسالة الفشل نفسها؛ لا تُضِف استثناءً.

---

## `MemberFinancialSummaryDto`

| الحقل | الحالة الآن | البديل | شرط الحذف |
|---|---|---|---|
| `remainingCoverage` | مرادف غير مقصوص لـ`actualRemaining` | `actualRemaining` للعرض المحاسبي، `reservableAvailable` لأي قرار التزام جديد | لا مستهلك خارجي |
| `totalPaid` | `null` دائماً + `claimPaymentAttribution = NOT_SUPPORTED` | لا بديل — انظر أدناه | لا مستهلك خارجي |
| `totalApproved` | `null` دائماً | وحدة المطالبات | لا مستهلك خارجي |
| `totalClaimed` | `null` دائماً | وحدة المطالبات | لا مستهلك خارجي |

### لماذا `remainingCoverage` مهجور لا محذوف الآن

اسمه لا يقول أي رقم يعنيه، وهكذا وصل إلى شاشة إدخال مطالبة وهو يحمل الرقم
المحاسبي. صار الآن مرادفاً غير مقصوص لـ`actualRemaining` — قيمته صحيحة،
واسمه فقط هو المشكلة. الحذف يكسر عقداً عاماً، وهذا قرار لا يُتخذ ضمن إصلاح.

### لماذا `totalPaid` لا يمكن إصلاحه هنا

كان يجمع `approvedAmount` لمطالبات حالتها `SETTLED` — أي يُبلّغ عن تغيّر حالة
بوصفه حركة مال، ولا يرى دفعة جزئية إطلاقاً. واستبداله بمصدر حقيقي غير ممكن على
مستوى المستفيد:

- `PaymentRecord` و`ProviderPaymentAllocation` مفتاحهما
  (جهة عمل + مقدم خدمة + سنة + شهر)، بلا حقل مطالبة ولا مستفيد.
- `Claim.paidAmount` يكتبه مسار واحد فقط
  (`ClaimReviewService.settleClaim`)؛ المسار العام لتغيير الحالة ومسار الدفعة
  الشهرية يتركانه فارغاً.

أي أن `SUM(Claim.paidAmount)` سيُظهر مطالبات مسوّاة فعلاً على أنها غير مدفوعة،
وتوزيع دفعة شهرية مجمّعة على مطالبات مستفيد بعينه اختراعُ إسناد مالي.

**الإسناد الحقيقي ملف مستقل**، يحتاج علاقة صريحة في المخطط:

```
Payment / Allocation  →  Claim  →  Member
```

ولا يُبنى بتقدير أو توزيع افتراضي.

## متى تُحذف

عند أول إصدار API منضبط بعد التحقق من عدم وجود مستهلك خارجي. الحذف يشمل في
نفس الالتزام:

1. الحقول من `MemberFinancialSummaryDto`.
2. أسطرها من `MemberFinancialSummaryService`.
3. مدخلاتها من `FORBIDDEN_READS` في الاختبار البنيوي.
4. صفوفها من هذا الملف.

إذا بقي `claimPaymentAttribution` وحده بلا `totalPaid`، فقد فقد معناه — يُحذف
معها.
