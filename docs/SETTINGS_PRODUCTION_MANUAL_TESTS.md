# تقرير الاختبارات اليدوية لإغلاق ملف إعدادات النظام

التاريخ: 2026-08-02  
النطاق: إعدادات النظام، بوابة مقدم الخدمة، رسائل الحفظ، وإخفاء المسارات القديمة.

## نتيجة التحقق الآلي قبل التسليم

- تم حذف تبويب “قواعد التغطية المالية” من شاشة الإعدادات.
- تم إصلاح حفظ `ELIGIBILITY_STRICT_MODE=false` بحيث لا يتحول إلى قيمة فارغة.
- تم جعل `LOGO_URL` اختيارياً فعلياً؛ تركه فارغاً يعني استخدام الشعار الافتراضي.
- تم ربط خيار “تفعيل إضافة الموافقات المسبقة المباشرة” بحارس Backend، وليس بالواجهة فقط.
- تم إضافة خيار “إظهار مسار دفعات المطالبات الداخلي” إلى تبويب بوابة مقدم الخدمة.
- تم تمرير:
  - `mvn -q -DskipTests compile`
  - `npx eslint src/pages/settings/SystemSettingsPage.jsx`
  - `npm run build`

## الاختبارات اليدوية المطلوبة منك

نفّذ هذه الاختبارات على قاعدة البيانات المحلية التي تعمل عليها فعلياً.

### 1. حفظ إعدادات النظام بدون رسائل غامضة

الخطوات:

1. افتح: إعدادات النظام.
2. اترك رابط الشعار فارغاً.
3. غيّر “وضع الاستحقاق الصارم” بين مفعل ومعطل.
4. اضغط “حفظ وتطبيق التغييرات”.

المتوقع:

- تظهر رسالة نجاح واضحة.
- لا تظهر رسائل:
  - `Invalid request parameter value`
  - `Setting ELIGIBILITY_STRICT_MODE must be true or false`
  - `Setting LOGO_URL cannot be empty`

فشل الاختبار إذا:

- ظهرت رسالة إنجليزية غامضة.
- فشل الحفظ عند إلغاء تفعيل الاستحقاق الصارم.
- فشل الحفظ عند ترك الشعار فارغاً.

### 2. التأكد من حذف تبويب قواعد التغطية المالية

الخطوات:

1. افتح إعدادات النظام.
2. راجع التبويبات العلوية.

المتوقع:

- لا يظهر تبويب “قواعد التغطية المالية”.
- تبقى التبويبات الأخرى تعمل بترتيب طبيعي:
  - معلومات المؤسسة
  - قواعد الاستحقاق
  - المحرك التشغيلي
  - إعدادات التقارير
  - بوابة مقدم الخدمة
  - إعدادات البريد
  - المظهر

فشل الاختبار إذا:

- ظهر التبويب المحذوف.
- فتح أي تبويب يعرض محتوى تبويب آخر بسبب خلل في الفهارس.

### 3. خيار إظهار/إخفاء بوابة مقدم الخدمة

الخطوات:

1. من إعدادات النظام > بوابة مقدم الخدمة.
2. عطّل خيار “إظهار/إخفاء بوابة مقدم الخدمة”.
3. سجّل دخول بمستخدم مقدم خدمة.
4. راجع القائمة الجانبية وحاول فتح مسار من مسارات البوابة مباشرة.
5. أعد تفعيل الخيار وكرر الدخول.

المتوقع عند التعطيل:

- تختفي بوابة مقدم الخدمة من القائمة للمستخدم المخول.
- مسارات البوابة لا تسمح بالعمل لمستخدم مقدم الخدمة.

المتوقع عند التفعيل:

- تظهر بوابة مقدم الخدمة من جديد.
- يستطيع مستخدم مقدم الخدمة الوصول حسب صلاحياته وربطه بالمرفق.

فشل الاختبار إذا:

- ظلّت البوابة ظاهرة بعد التعطيل.
- اختفت من القائمة لكن بقيت APIs تعمل لمقدم الخدمة.
- لم تظهر بعد إعادة التفعيل.

### 4. خيار المطالبات المباشرة من بوابة مقدم الخدمة

الخطوات:

1. فعّل بوابة مقدم الخدمة.
2. عطّل “تفعيل إضافة المطالبات المباشرة”.
3. ادخل كمستخدم مقدم خدمة.
4. افتح سجل الزيارات أو شاشة البوابة التي تحتوي زر إنشاء مطالبة.
5. جرّب إنشاء مطالبة مباشرة.
6. أعد تفعيل الخيار وكرر المحاولة.

المتوقع عند التعطيل:

- لا يظهر زر إنشاء مطالبة مباشرة، أو يظهر معطلاً حسب تصميم الصفحة.
- لو تم استدعاء API مباشرة يجب أن يرفض الطلب برسالة واضحة.

المتوقع عند التفعيل:

- يظهر زر إنشاء مطالبة.
- يمكن الانتقال إلى شاشة إدخال المطالبة.

فشل الاختبار إذا:

- الزر يظهر ويعمل رغم التعطيل.
- الواجهة تخفي الزر لكن API تقبل الطلب.

### 5. خيار الموافقات المسبقة المباشرة من بوابة مقدم الخدمة

الخطوات:

1. فعّل بوابة مقدم الخدمة.
2. عطّل “تفعيل إضافة الموافقات المسبقة المباشرة”.
3. ادخل كمستخدم مقدم خدمة.
4. افتح سجل الزيارات أو شاشة تقديم موافقة مسبقة.
5. جرّب إنشاء موافقة مسبقة.
6. أعد تفعيل الخيار وكرر المحاولة.

المتوقع عند التعطيل:

- لا يظهر زر إنشاء موافقة مسبقة، أو يظهر معطلاً.
- لو تم استدعاء API مباشرة يجب أن يرفض الطلب برسالة واضحة.

المتوقع عند التفعيل:

- يظهر زر إنشاء موافقة مسبقة.
- يمكن فتح شاشة تقديم الموافقة.

فشل الاختبار إذا:

- الموافقات يمكن إنشاؤها من مقدم الخدمة رغم تعطيل الخيار.

### 6. خيار أصناف الموافقات المسبقة

الخطوات:

1. فعّل بوابة مقدم الخدمة والموافقات المباشرة.
2. فعّل خيار “أصناف بموافقة مسبقة”.
3. افتح شاشة تقديم موافقة مسبقة من البوابة.
4. افتح قائمة الخدمات.
5. عطّل الخيار وكرر فتح القائمة.

المتوقع عند التفعيل:

- تظهر فقط الخدمات/الأصناف التي تتطلب موافقة مسبقة.

المتوقع عند التعطيل:

- تظهر جميع الأصناف/الخدمات المتاحة حسب عقد مقدم الخدمة.

فشل الاختبار إذا:

- لم يتغير عدد أو نوع الخدمات عند تبديل الخيار.

### 7. خيار إظهار مسار دفعات المطالبات الداخلي

الخطوات:

1. من تبويب بوابة مقدم الخدمة، عطّل “إظهار مسار دفعات المطالبات الداخلي”.
2. ادخل كمستخدم داخلي مخول.
3. راجع القائمة الجانبية لمسار دفعات المطالبات.
4. جرّب فتح مسار الدفعات مباشرة من الرابط إن كان محفوظاً لديك.
5. أعد تفعيل الخيار.

المتوقع عند التعطيل:

- يختفي مسار الدفعات من القائمة.
- API الدفعات ترفض العمل برسالة واضحة.

المتوقع عند التفعيل:

- يظهر مسار الدفعات ويعود للعمل.

فشل الاختبار إذا:

- المسار يظل ظاهراً أو يعمل رغم التعطيل.
- لا يعود بعد إعادة التفعيل.

## معيار الإغلاق

يُعتبر ملف الإعدادات مغلقاً إنتاجياً إذا نجحت الاختبارات السبعة أعلاه دون رسائل غامضة ودون اختلاف بين الواجهة والباك إند.

نسبة الجاهزية بعد نجاح الاختبار اليدوي: 98–99%.

الملاحظة الوحيدة غير المانعة:

- بناء الواجهة ينجح، لكن Vite يعرض أحجام chunks كبيرة لبعض الحزم العامة مثل Excel/PDF/MUI. هذا تحسين أداء لاحق وليس خللاً وظيفياً في الإعدادات.
